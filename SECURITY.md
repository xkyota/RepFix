# Security policy

RepFix executes reviewed commands in the caller's environment and stores local debugging evidence. Reports, screenshots, traces, and logs may contain private data. Review and redact them before sharing.

## Supported versions

Security fixes target the latest code on `main`. Older commits and unpublished builds are not maintained separately.

## Reporting a vulnerability

Use [GitHub's private vulnerability reporting](https://github.com/xkyota/RepFix/security/advisories/new) to contact the maintainers. Include a concise impact description, reproduction steps, affected versions or commits, and a proposed fix if available. Do not include real secrets or third-party data. Please allow time for a coordinated fix before public disclosure.

If private reporting is unavailable in the repository settings, contact the repository owner privately through the contact method listed on their [GitHub profile](https://github.com/xkyota). Do not open a public issue containing exploit details.
