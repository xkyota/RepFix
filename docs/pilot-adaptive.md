# Agent pilot: adaptive verification

Run on 2026-10-13 with the candidate helper from this branch, Node.js 24.16.0, Python 3, and Codex CLI 0.162.0-alpha.17.2 on macOS. Claude Code was unavailable (`command -v claude` returned no executable), so no Claude agent run, cross-host timing comparison, or Claude token count was measured.

Codex received two isolated, clean copies of repository debugging fixtures. Its prompts stated the reported behavior, pointed to the candidate RepFix skill and CLI, and asked the agent to investigate, choose its own edit, capture RED/GREEN evidence, run a relevant regression, and report. The prompts did not provide patches. These were agent runs; the separate [recorder benchmark](benchmark-adaptive.md) uses fixed edits.

The Python session's elapsed time contains a long host stream interruption. Codex logged `stream disconnected before completion: idle timeout waiting for websocket` and retried shortly before its report. The recorded child commands took only 168 ms in total. The elapsed remainder cannot be attributed to model reasoning or to RepFix; it includes this interruption. No reliable agent speedup or p95 claim follows from these two tasks. The Python plan extension happened before the first recorded command; the late extension gate is tested separately in `test/adaptive.test.mjs`.

The independent assessment compared the agent edits against the untouched repository fixtures, checked that original assertions were preserved, ran tests outside the agent, and inspected each `report.json`. This found no false VERIFIED claim in these two cases. It does not establish correctness for larger projects or untested behavior. Full event logs and `.repfix/` evidence stayed local under `/private/tmp/repfix-pilot/`; they were not published with the package.

## Reproduce with Codex or Claude Code

1. Check out this candidate revision and build the helper with `npm run build`. Make fresh isolated copies of `test/fixtures/pagination/` and `test/fixtures/python-cart/` for **each** host. The starting SHA-256 values were `5ed96dca92683dea22b7746ec805a2db7f46c4a1c04e7f755ac8e0738630b64f` (`paginate.mjs`), `a5e87e572346fb82eb8f5c290696f0e1fc0ff09e296df7b01d7023cbd10b50df` (`regression.test.mjs`), `48d9f9c09826f0eaa5f1060308c554975910a2b2782ce7b8cb910c70270f8d97` (`cart.py`), and `6054c8fd0d07b2d44fc024e7a82ef0ae4415be2d979dc789583d1eba0f53db62` (`test_regression.py`). Check these before each run.
2. Give each host the same task prompt: “Investigate and fix [the full final pagination page omits its final item / a new customer's cart inherits an earlier customer's items]. Read this candidate's `skills/repfix/SKILL.md` and `references/commands.md`. Use its built CLI for RED, confirmation, GREEN, relevant regressions, and report. Choose your own edits and commands after inspection. Preserve existing assertions. Do not use a predetermined patch or claim VERIFIED without the helper report. Return the session path and limits.” Keep the host's normal sandbox/permission policy and record any exceptions.
3. For Codex, run the prompt in each fixture with `codex exec --sandbox workspace-write --skip-git-repo-check -C FIXTURE --json -` and capture its JSONL events. For Claude Code, use its available interactive or noninteractive agent entry point in the same clean fixture and capture the equivalent action/usage record. Do not replay a patch or CLI transcript as a substitute for an agent run.
4. Record host version, start/end wall time, exposed token counters, completed command/file-edit actions, RepFix CLI calls, selected/current profile, escalation events, plan history, recorded child commands, and report status. Mark unavailable counters as unavailable. Independently diff source and oracle files against the starting copy, run the full fixture tests plus the targeted checks above, and score correctness and any false VERIFIED claim without trusting the agent's final message.

Only the Codex rows above were measured. The same protocol is ready for a Claude Code run once that host is available.
